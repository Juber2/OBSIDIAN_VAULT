# Modelos, Chat, Work y Codex

## Tres decisiones diferentes

No confundas:

- **Superficie:** Chat, Work o Codex.
- **Modelo:** motor disponible en tu plan.
- **Esfuerzo/modo:** cuánto razonamiento, velocidad o autonomía se aplica.

Un modelo potente dentro de Chat sigue sin tener automáticamente acceso a tu repositorio. Codex con un modelo más rápido puede superar a Chat en una feature porque ve los archivos y ejecuta tests.

## Elegir por forma de tarea

| Tarea | Prioridad |
|---|---|
| Rename, formato, consulta corta | Velocidad |
| Explicar un módulo | Contexto + claridad |
| Bug intermitente | Razonamiento + herramientas |
| Arquitectura/migración | Profundidad + fuentes + validación |
| Feature multiarchivo | Codex + toolchain |
| Review de seguridad | Profundidad + evidencia + alcance autorizado |
| Muchas tareas similares | Eficiencia/costo + automatización |

## Cómo aprovechar selección y esfuerzo

1. Usa un modo rápido para navegación, transformaciones y correcciones pequeñas.
2. Sube el esfuerzo cuando el problema tenga hipótesis, trade-offs o pasos dependientes.
3. Usa Codex para tareas donde ejecutar importa más que explicar.
4. Usa Work para producir un entregable compuesto desde múltiples fuentes.
5. Evalúa con problemas reales; no mantengas siempre el máximo esfuerzo por costumbre.

## Modelos cambiantes

Los nombres y defaults cambian. Guarda en tus notas **criterios**, no recomendaciones eternas como «siempre usa X». Al evaluar:

- porcentaje de criterios cumplidos;
- correcciones humanas;
- tokens/uso/costo;
- latencia;
- capacidad de usar herramientas;
- calidad tras ejecutar tests.

## Modelo ≠ producto

El mismo ecosistema puede ofrecer:

- conversación alineada a ChatGPT;
- modelos de razonamiento;
- variantes optimizadas para código;
- agentes con herramientas y contexto persistente.

La mejor elección es la combinación que termina la tarea correctamente, no la que escribe la respuesta más impresionante.
