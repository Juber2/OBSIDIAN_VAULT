# Cómo estudiar Angular con este vault

## Forma recomendada

Estudia por módulos. Primero lee el índice del módulo, luego las notas técnicas, después realiza la práctica. No marques un tema como completo hasta escribir un ejemplo propio.

## Regla de avance

Cada nota debe terminar en algo verificable: un snippet, un mini componente, una prueba, una decisión o un refactor.

## Orden sugerido

1. Requisitos previos.
2. TypeScript y CLI.
3. Componentes/templates.
4. Servicios/DI/HTTP.
5. Routing/forms.
6. RxJS/signals/state.
7. Arquitectura/performance/testing/senior.

## Errores comunes

- Leer sin practicar
- Querer memorizar todas las APIs

## Práctica

- [ ] Crear una app sandbox para practicar cada módulo

## Ampliación práctica

En **Cómo estudiar Angular con este vault**, la idea es llevar la nota más allá de una definición. Úsala para responder tres preguntas: qué problema resuelve, cómo se ve en código real y qué error debes evitar en un proyecto empresarial.

## Criterio de uso

No adoptes una técnica solo porque es moderna. Primero identifica el problema: estado difícil, render lento, formulario complejo, rutas desordenadas, permisos confusos o deuda legacy. Luego elige la herramienta Angular que reduzca ese problema con el menor costo razonable.

## Ejercicio

Escribe un ejemplo mínimo propio y luego mejóralo: agrega estado de error, tipado correcto y una prueba o checklist. Ese pequeño ciclo vale más que leer la nota sin practicar.
