# Proyecto Capstone Angular Empresarial

## Objetivo

Construir una app empresarial genérica: login, dashboard, usuarios, cursos, formularios, roles, tablas, búsqueda, estado, testing y performance.

## Stack esperado

Standalone components, rutas lazy, control flow moderno, typed forms, HttpClient, interceptors, guards, Signals, RxJS, tests y @defer.

## Backlog por etapas

1. Shell y routing.
2. Login y sesión.
3. CRUD con API fake/real.
4. Forms y validaciones.
5. Estado y filtros.
6. Testing.
7. Performance y arquitectura.

## Terminado significa

README, ADRs, checklist de PR, tests de flujos críticos, build limpio y explicación de tradeoffs.

## Uso en proyectos reales

Esta nota funciona como material de consulta durante diseño, implementación y code review. No está pensada para leerse una sola vez, sino para volver cuando tengas que tomar una decisión o revisar una PR. En **Proyecto Capstone Angular Empresarial**, la clave es convertir criterio técnico en acciones observables.

## Señales de buena aplicación

- La decisión queda escrita y se entiende el contexto.
- El código resultante reduce riesgo, no solo cambia estilo.
- Hay un responsable claro para mantener la decisión.
- El equipo puede explicar el tradeoff sin depender de una persona.

## Señales de mala aplicación

- Se usa como checklist mecánico sin pensar.
- Se bloquean PRs por preferencias personales.
- Se agregan patrones sin problema real.
- Se documenta mucho, pero el código sigue sin tests ni observabilidad.

## Pregunta de cierre

Antes de aplicar esta referencia, pregúntate: ¿qué riesgo concreto estoy reduciendo? Si no puedes responderlo, quizá estás agregando proceso y no calidad.
