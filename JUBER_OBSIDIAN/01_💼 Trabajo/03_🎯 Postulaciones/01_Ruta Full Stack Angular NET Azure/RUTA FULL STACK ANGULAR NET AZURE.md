# Ruta laboral Full Stack — Angular + .NET + Java + Cloud

Esta ruta no busca estudiar todas las tecnologías posibles. Su objetivo es dejarte listo para **cualquiera de las 14 vacantes activas registradas en [[POSTULACIONES]]**, no solo para un perfil ideal teórico. Se actualiza con lo que [[16 - Radar acumulativo de vacantes]] confirma como demanda real, no con lo que suena interesante.

> [!important]
> Las postulaciones comienzan el **31 de agosto de 2026**. El estudio ocurre en paralelo; no es una condición previa para empezar a aplicar.

> [!tip] Si solo vas a leer una nota
> Empieza por [[Guía Maestra - Mi Recomendación de Preparación]] — es la lectura de por dónde empezar, en qué orden y qué preguntas esperar, sin navegar los 17 módulos.

> [!tip] Por qué ya no dice solo ".NET"
> El radar acumulado deja de tratar a Java/Spring como "rama condicionada": aparece en **7 de 14** vacantes, casi empatado con .NET (8 de 14). Presentarte solo como ".NET" descarta parte de tus oportunidades.

> [!warning] Pero Java todavía no es un eje demostrable — corregido el 31/08/2026
> Con el CV a la vista ([[23 - Mi CV frente a las 14 Vacantes]]): **no hay experiencia profesional en Java backend**, solo Android con Java/Kotlin. .NET es el eje **real y demostrable** (4 experiencias, ~5 años); Java es **aspiracional**.
>
> En la práctica: las vacantes .NET (Entelgy, TCS, TSOFT, Periferia) van primero porque ahí competís con evidencia. Java se estudia igual, pero se presenta como formación en curso, nunca como experiencia.

## Perfil objetivo

**Full Stack / Backend Developer políglota** con dos ejes backend intercambiables según la vacante:

- Angular y TypeScript en frontend — presente en 5 de 14 vacantes.
- **Eje backend A:** C#, ASP.NET Core y EF Core.
- **Eje backend B:** Java, Spring Boot y JPA/Hibernate — mismo nivel de exigencia que el eje .NET, no un "nice to have".
- SQL Server, PostgreSQL y Oracle según el cliente; NoSQL solo cuando el proyecto lo justifica.
- Azure como eje cloud principal, con vocabulario transferible a AWS y GCP (ambos aparecen en vacantes reales).
- Docker, CI/CD, mensajería con Outbox/idempotencia y observabilidad para entrega reproducible.
- Testing, seguridad OWASP, diseño de APIs y diagnóstico de producción — exigidos en 6-7 de las 14 vacantes cada uno.

## Qué agregar realmente al stack

### Obligatorio ahora

- Testing unitario, de integración y frontend.
- Autenticación y autorización con OAuth 2.0/OIDC/JWT.
- CI/CD.
- Observabilidad con logs estructurados, métricas y trazas.
- Azure App Service o Container Apps, Azure SQL, Key Vault, Storage y Application Insights.
- Docker multi-stage, Compose y health checks.
- Git, pull requests y code review.
- **Java + Spring Boot al mismo nivel que ASP.NET Core** — ver [[06 - Ruta Java Spring Boot como segundo eje backend]]. Ya no es diferenciador, es núcleo.
- Microservicios con límites claros (base de datos por servicio, comunicación síncrona/asíncrona, sin sobreingeniería) — aparece en 7 de 14 vacantes.

### Siguiente multiplicador

- PostgreSQL a nivel desarrollador y Oracle/PL/SQL básico (4 vacantes lo piden explícitamente).
- Redis y estrategias de caché (Cache-Aside).
- Azure Service Bus / Kafka / RabbitMQ, trabajos asíncronos y patrón Outbox con idempotencia y DLQ.
- Bicep o Terraform básico.
- Performance, resiliencia e idempotencia.
- Postman/Newman dentro del pipeline (3 vacantes lo mencionan como herramienta de equipo).
- Inglés técnico para entrevista y documentación (filtro duro en al menos una vacante).

### Solo cuando una vacante o proyecto lo justifique

- MongoDB o una base documental.
- Kubernetes/AKS/OpenShift profundo (RBAC, routes, diagnóstico) — 2 vacantes.
- GCP y Google Pub/Sub — crítico solo para ISP Consulting.
- AWS serverless (Lambda, API Gateway) — crítico solo para Cuidafarma; en el resto es vocabulario transferible.
- DB2 y BIAN — filtros de producto muy específicos, no se estudian en profundidad sin avanzar en esa candidatura puntual.
- Elasticsearch/OpenSearch autoadministrado.
- Migración legacy (VB6/WinForms) — solo si Periferia avanza.

## Kit universal — listo para cualquiera de las 14 vacantes

Esto es lo nuevo: en vez de preparar 14 discursos distintos, un kit corto que cubre el terreno común y se adapta en minutos por candidatura.

### El núcleo que nunca cambia (aparece en la mayoría de las 14)

| Capacidad | Apariciones en el radar | Por qué es innegociable |
|---|---:|---|
| REST/JSON e integraciones entre sistemas | 10/14 | Es el idioma común a todas las vacantes, sin importar el lenguaje |
| Bases de datos relacionales (SQL, índices, transacciones) | 11/14 | Ninguna vacante prescinde de una base relacional bien manejada |
| Microservicios / arquitectura de servicios | 7/14 | Backend enterprise moderno se asume, no se pregunta si sabes qué es |
| Java/Spring Boot | 7/14 | Segundo eje backend, casi empatado con .NET |
| .NET/C# | 8/14 | Primer eje backend |
| Seguridad (OAuth/JWT/OWASP) | 7/14 | Filtro técnico transversal en entrevistas |
| CI/CD | 7/14 | Se asume como parte del oficio, no como plus |
| Angular | 5/14 | Frontend dominante cuando la vacante pide full stack |
| Testing (unit/integration) | 6/14 | Diferencia mid de senior en cualquier stack |
| Git / PRs / code review | 6/14 | Higiene de equipo básica |

### Tres discursos de 45 segundos (elige según la vacante, no repitas siempre el mismo)

> **Full Stack .NET + Angular:** "Full stack orientado a Angular y .NET, con APIs ASP.NET Core, EF Core y frontend Angular, fortaleciendo Docker, Azure, CI/CD y observabilidad para entregar el ciclo completo."

> **Backend Java/Spring:** "Backend con Java y Spring Boot — APIs REST, JPA/Hibernate, seguridad con JWT/OAuth2 y microservicios — con la misma disciplina de testing, CI/CD y cloud que aplico en .NET, adaptable al stack del equipo."

> **Full Stack políglota (Stefanini, TSOFT, Entelgy, BIAN, Full Stack Senior):** "Full stack políglota — Angular en frontend, Java o .NET en backend según el proyecto — con foco en integraciones, seguridad, arquitectura y despliegue en la nube, no en una sola tecnología aislada."

### Chequeo de una hoja antes de postular a cualquiera de las 14

- [ ] ¿El anuncio pide .NET, Java o ambos? Usa el discurso correspondiente, no el genérico por defecto.
- [ ] ¿Hay un filtro duro (años, inglés, sector financiero/banca, tecnología legacy)? Revisar la nota puntual de esa vacante antes de invertir tiempo de estudio.
- [ ] ¿El requisito cloud es Azure, AWS o GCP? Explicar el concepto en abstracto y mapear al proveedor pedido, sin fingir dominio de tres nubes.
- [ ] ¿Pide mensajería (Kafka/RabbitMQ/Service Bus)? Responder con Outbox + idempotencia + DLQ, que es transferible entre brokers.
- [ ] CV adaptado con [[13 - Sistema de postulación por vacante]] antes de enviar.

## Definición de “listo para entrevista”

Un tema está listo cuando puedes:

1. Explicarlo sin leer.
2. Mostrar dónde lo utilizaste.
3. Describir un error o trade-off real.
4. Implementar una versión mínima.
5. Diagnosticar qué harías si falla.

Marcar una nota como leída no cuenta como evidencia.
