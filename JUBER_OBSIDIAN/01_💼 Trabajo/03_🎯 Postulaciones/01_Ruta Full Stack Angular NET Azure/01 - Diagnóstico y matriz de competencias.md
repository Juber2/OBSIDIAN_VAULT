# Diagnóstico y matriz de competencias

## Escala honesta

| Nivel | Evidencia |
|---|---|
| 0 — No conozco | No puedo explicarlo |
| 1 — Reconozco | Entiendo términos, pero necesito guía |
| 2 — Implemento | Puedo construir una solución básica solo |
| 3 — Producción | He resuelto fallos, seguridad o performance |
| 4 — Diseño y enseño | Comparo alternativas y guío a otros |

Para postular como mid-level, el núcleo debe estar principalmente en 2-3. No hace falta nivel 4 en todo.

## Evidencias válidas

- Repositorio con commits propios y README ejecutable.
- Pull request o code review.
- Aplicación desplegada.
- Test automatizado que protege un flujo importante.
- Dashboard, alerta o traza que ayuda a diagnosticar un fallo.
- ADR que explica una decisión y sus alternativas.
- Historia de producción explicada con contexto, decisión y resultado.

## Evidencias débiles

- “Vi un curso”.
- “Tengo una nota en Obsidian”.
- Proyecto copiado sin poder modificarlo.
- Lista de veinte tecnologías sin un caso de uso.
- Certificación sin práctica demostrable.

## Resultado de la evaluación

Clasificar cada brecha:

- **Cerrar ya:** aparece con frecuencia y bloquea entrevistas.
- **Demostrar mejor:** sabes hacerlo, pero el CV/GitHub no lo prueba.
- **Aprender después:** valiosa, pero no cambia las postulaciones actuales.
- **Ignorar:** moda o herramienta aislada sin demanda real en tus vacantes.
